updated: 2026-09-28T11:00

- (direction) Build only demonstrated source-lifecycle improvements: official fallback and retry recovery, consistent source contract, and status reporting.
- (capability) CAP-1: An approved source transfer can recover from a temporary official endpoint block using an equivalent official URL while preserving source evidence and checksums.
- (capability) CAP-2: An operator can see a source’s intended scope, retained artifacts, failures, and published coverage in one status report.
- (constraint) YAML remains the human-reviewed contract; the database artifact ledger remains the factual record of actual bytes, checksums, and states.
- (constraint) No third-party mirror replaces the original government endpoint as evidence; alternate official endpoints may be used only when explicitly equivalent.
- (constraint) Unknown sizes, content-type mismatches, and capacity failures stop the transfer rather than being guessed or ignored.
- (note) The current ACS transfer retained 2,277 artifacts before one official URL returned a Cloudflare HTML rejection page; an official legacy URL for the same file returned an application/zip response.
- (event) Coherence validation passed: three capabilities have testable success signals, constraints bend source and ledger choices, and non-goals exclude mirror replacement and registry duplication.
- (event) Preservation validation passed: operator direction on fallback recovery, YAML contracts, database ledger, status reporting, capacity safety, and no premature source expansion is represented in SPEC.md or its companion.
