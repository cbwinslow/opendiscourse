- (direction) Operator (2026-09-19 handoff): write the bmad-spec for ADR-0005, then build the identity fix first. Input is rich (ADR-0005 accepted with changes, reviewed by Fable and Codex; docs/rebuild-proof-2026-09-19.md); mode express, no elicitation.
- (decision) Spec slug order-independent-identity; ADR-0005 is the source and stays the rationale. Companions: assertion-model.md (tables, precedence, resolver rules) and writers-and-stories.md (writer inventory, story order).
- (capability) CAP-1: a person is found by any known identifier (BioGuide, OCD, others in core.person_identifier), never by name, so loading legislators, OpenStates and Congress.gov in any order yields the same person and identifier sets (Problem A; ~722 duplicates avoided).
- (capability) CAP-2: an identifier set that resolves to two existing persons, or contradictory assertions, is never guessed: the association aborts, a conflict record is written, and it stays visible in the conflict report.
- (capability) CAP-3: a reviewed duplicate is merged in one transaction under the person lock (repoint person_identifier, bill_sponsorship, membership, member_vote; preserve colliding member_vote rows in a merge-audit table; delete duplicate; ledger every count). Only known case: Stutzman in inventory/identity_exceptions.yaml (applied: false).
- (capability) CAP-4: loaders write typed name assertions (core.person_name_source, core.geography_name_source) with dataset, vintage, and evidence (artifact OR payload, plus run), idempotent by natural key; losing values are kept.
- (capability) CAP-5: precedence per entity, attribute, geography_type is tracked in inventory/precedence.yaml synced to catalog.attribute_precedence; resolution is rank, then source_vintage DESC, then natural key COLLATE C; a dataset with assertions and no precedence row fails closed.
- (capability) CAP-6: resolved columns (person full/given/family name, geography name) are materialised with a name_source_id winner pointer; only the resolver writes them; research-db resolve [--dry-run] is idempotent and reports changed rows.
- (capability) CAP-7: backfill is a rerun of the loaders (never from stage.*), preceded by a pre-image CSV and resolve --dry-run whose diff is asserted (246 people, no geography name changes), then applied and recorded; rollback is a precedence flip.
- (capability) CAP-8: the rebuild kit verify step runs a final global resolve --dry-run that must report zero changes and compares resolved values with no exclusions.
- (constraint) Never match by name (ADR-0002, AGENTS.md); federal person joins need BioGuide; FEC/disclosure name assertions call identitygate.require_person_join first.
- (constraint) Every person creator and identifier writer takes the same advisory lock (precedent repositories/people.py promote_legislators). Today sync_openstates_federal_people and the Congress.gov upsert take none.
- (constraint) Resolver runs as its own short transaction after the loader commits, under pg_advisory_xact_lock(hashtextextended('resolve:<entity>',0)), updating non-key columns only, ordered by PK, only changed rows. Consistency is eventual by design; resolve is a pure function of committed assertions.
- (constraint) Resolved-column enforcement: application role has column UPDATE revoked, resolver is a narrowly owned function holding the privilege; a BEFORE UPDATE trigger with SET LOCAL flag is only an accidental-write guard, not security. Creating a person still inserts full_name (NOT NULL) plus its assertion in one statement.
- (constraint) Do not use ingest.current_artifact for tie-breaks (it orders versions of one artifact key; TIGER has 39 keys and 96 CBSA names differ across vintages). name resolves short then full so partial rebuilds never show NULL. ZCTA name assertions skipped.
- (constraint) Retained artifact files are never touched; wiping and re-ingesting derived rows is authorized but recorded. Migration is expand/contract, forward-only, guarded downgrade; restore = nightly dump plus pre-image CSV. Alembic for schema; raw psycopg for set-based SQL under sql/query/; new geography SQL moves out of inline ingestion/*.py.
- (constraint) Do not source assertions from stage.*: the kit drops ~37 GB of stage duplicates including tiger_feature. Backfill happens before any stage drop.
- (decision) Rule for the future: any attribute two sources can describe for one entity gets an assertion table and precedence entry in the same change that adds the second source; opendiscourse-schema-change and opendiscourse-connector skills say so.
- (decision) Precedence start: person official name congress.legislators > congress.legislation (Congress.gov) > openstates.legislation; geography short name census.tiger NAME (PEP CTYNAME supplies full, not short); geography full name TIGER NAMELSAD (county, CBSA; loader must start reading it) > PEP CTYNAME > ACS NAME. Until operator decides, resolver reproduces today's live names.
- (assumption) Stutzman is the only OCD-only person; ~722 other OpenStates people already list a BioGuide id in opencivicdata_personidentifier which the loader ignores; looking up by it is the fix (Fable-verified live counts; Codex sandbox could not query DB).
- (question) Operator: does core.person.full_name show the common name ('Mike Lawler', mostly OpenStates) or the official one ('Michael Lawler', congress-legislators)? Recommendation: common, official kept and exposed beside it. Does not block the identity fix (story 1).
- (question) One live person has no BioGuide id (1 of 12,771) and 9,841 person_identifier rows have no artifact; is the BioGuide-less person the Stutzman duplicate, and should artifact-less identifiers be backfilled with evidence?
- (direction) Non-goals: no scorecards, NLP, embeddings; no new sources; no Connector/run-ledger redesign; no MDM/record-linkage or name-matching library; no generic EAV table; no view replacing core.person/core.geography; no rebuild-kit phases beyond its verify hook.
