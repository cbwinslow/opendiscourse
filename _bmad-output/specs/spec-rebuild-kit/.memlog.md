- (direction) Operator condition (PROJECT-STATE step 1, storage-and-backup-plan): stage duplicates (~37 GB: cbp_row 22, tiger_feature 10, acs_bulk_row 5) may be dropped only after a documented, tested rebuild exists. Also the portability goal: anyone runs it on their own machine.
- (direction) Mode: express (operator delegates judgment; full context already in repo). Gaps become open questions.
- (capability) CAP-1: one ordered, documented command sequence takes an empty DATA_ROOT and empty database to the loaded state of every v1 source, download -> inventory -> ingest, resumable, idempotent.
- (capability) CAP-2: the kit reads its scope (which sources, which Census tables/geographies/years, which Congresses, FEC families/cycles) from tracked config, not from gitignored lake meta/ plans.
- (capability) CAP-3: a verify step proves the rebuild: per-source row counts and checksums compared with the run ledger, coverage report and expected manifests; exits non-zero on mismatch.
- (capability) CAP-4: rebuilding stage/fact from raw is proven on a real loaded dataset so the ~37 GB stage duplicates can be dropped and re-created on demand.
- (capability) CAP-5: project skill opendiscourse-rebuild points agents at the command sequence and its rules; the skill holds no logic.
- (constraint) Every source is downloaded from its original government endpoint into the user's DATA_ROOT; no loader, default or inventory entry may read /mnt/storage or any machine-specific path (AGENTS.md). Today FEC (50 archives, 20 GB) and 16 BILLSTATUS rows are registered under /mnt/storage and no FEC downloader exists, so FEC needs a Connector-style downloader before the kit can claim it.
- (constraint) New sources are Connectors, not dispatcher branches; the kit orchestrates existing commands and Connectors, it adds no if/elif to cli.py, plans.py or registry.sync. Census families still use plan/preview/approve/download/stage/load; the kit calls them, and migrating them to Connectors is a separate story.
- (constraint) Raw artifacts are never deleted or overwritten; a rebuild reuses retained files whose checksum matches and downloads only what is missing or changed. Wiping derived rows (stage, fact, core rows a Connector loaded) is allowed and is recorded in the run ledger.
- (constraint) Acceptance runs against a scratch DATA_ROOT and a throwaway database, never the operator's live lake or warehouse; tests never write to the real lake (tests/conftest.py isolation, PR #51).
- (constraint) Politician-keyed rows stay behind identitygate.require_person_join; the kit loads no FEC-to-person joins, elections or crime (Epic 7 is not v1).
- (constraint) Downloads are polite (documented rate limits), API keys come from .env only and are never committed, and each source passes the capacity gate with a written size estimate before it downloads.
- (decision) Companion source-matrix.md holds the per-source table (dataset ids, origin, current download command, current ingest command, gap); the kernel cites it.
- (assumption) Scope of 'every loaded source' = census.acs_5_bulk (2021-2024), business_patterns, decennial DHC 2020, population_estimates, tiger, congress.govinfo_billstatus (108-119), congress.legislators, openstates.dump plus its dependent loads, fec.campaign_finance. BLS/FRED/Treasury series are small and already re-runnable via plans; optional steps.
- (assumption) The Census selection (which ACS tables, geographies, years) lives today in gitignored <lake>/meta/bulk-plans/*.yaml (about 30 plan files, up to 150 KB each) and must be captured into tracked config for the kit to be portable.
- (question) OpenStates: is the 10 GB public dump download plus restore into the separate openstates database part of the rebuild, or is the openstates provider snapshot an external prerequisite? core.person seeding and votes depend on it.
- (question) FEC scope for the kit: all 50 archives (2000-2026 across indiv/oth/pas2/oppexp, 20 GB) or the v1.1 subset? stage.fec_row (74 GB) is not among the ~37 GB droppable duplicates and its compact-layout decision (ADR-0003) is pending.
- (question) Acceptance size: a full rebuild takes hours and over 130 GB of downloads. Should acceptance use a bounded slice (one Congress, one ACS year, one TIGER layer) with the full run operator-only?
